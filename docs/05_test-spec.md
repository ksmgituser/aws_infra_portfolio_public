# 1. はじめに

## 1.1. 目的

本試験仕様書は、ポートフォリオシステム（ECS + RDS 構成）の構築・運用における品質を確認することを目的とする。  
試験対象は以下の通り。

| 対象領域 | 概要 |
| --- | --- |
| インフラ構築（Terraform） | AWSリソースが設計書通りに構築されていること |
| アプリケーション動作 | HTTPSアクセス・認証・CRUD操作が正常に機能すること |
| CI/CDパイプライン | GitHub Actions / CodeDeploy による自動デプロイが機能すること |
| セキュリティ・IAM | アクセス制御・最小権限・機密情報管理が設計通りであること |
| 障害・フェールオーバー | 障害発生時の自動復旧・フェールオーバーが機能すること |

## 1.2. 試験環境

| 項目 | 値 |
| --- | --- |
| AWSリージョン | ap-northeast-1（東京） |
| ECS クラスター | `dev-portfolio-container-ecs-cluster` |
| RDS インスタンス | `dev-portfolio-database-rds` |
| ALB | `dev-portfolio-network-alb` |
| アプリURL | `https://portfolio.infra-nikki.com` |
| 試験実施者 | |
| 試験実施期間 | |

## 1.3. 試験項目フォーマット

各試験項目は以下のフォーマットで記載する。

| 項目 | 説明 |
| --- | --- |
| 試験ID | `<章番号>-<連番>`（例：`2-01`） |
| 試験項目 | 試験内容の概要 |
| 前提条件 | 試験実施前に満たしておくべき条件 |
| 手順 | 試験の実施手順 |
| 期待結果 | 合格と判断する基準 |
| 実測値 | 試験実施時に確認した実際の値・結果 |
| 合否 | OK / NG / 課題 |
| 実施日時 | 試験を実施した日時 |
| 備考 | 特記事項・NG時の調査メモ等 |

## 1.4. 合否基準

- **OK**：期待結果をすべて満たしている
- **NG**：期待結果を満たさず、リリースブロッカーとなる問題がある
- **課題**：期待結果を満たさないが致命的ではなく、運用課題として持ち越す
- 試験結果は第7章「試験結果サマリー」に集約する

## 1.5. 再試験方針

NG項目の修正後は**全項目をやり直さず、影響範囲に絞って再試験**を行う。

| 修正内容 | 再試験範囲 |
| --- | --- |
| 特定リソースの設定変更（SG・パラメータ等） | NG となった試験項目のみ |
| ネットワーク構成の変更（VPC・サブネット・RT等） | 2章（インフラ構築確認）全体 ＋ 関連する3章・5章の項目 |
| ECS タスク定義・サービスの変更 | 2-09・2-10 ＋ 3章全体 |
| IAM ロール・ポリシーの変更 | 2-17 ＋ 5章全体 |
| CI/CD ワークフローの変更 | 4章全体 |
| RDS 設定の変更 | 2-12・2-13 ＋ 6-01・6-02 |

**再試験時の記録方針：**
- 再試験の結果は元の試験項目の実測値・合否・実施日時を上書きして更新する
- 備考欄に「再試験（初回 NG：YYYY-MM-DD）」と記載する
